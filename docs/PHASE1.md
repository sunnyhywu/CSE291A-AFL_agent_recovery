# Phase 1: Fault Injection and Propagation Measurement in Multi-Agent ALFWorld

CSE 291A, Option 5 (Failure Propagation and Recovery in Multi-Agent Systems).
Code: commit `fb4c95b`. All numbers come from `results/` and are regenerated by
`experiments/phase1.sh`; the full tables are in `results/phase1-tables.md`.

## 1. Question

Can tracking dependencies between agent results support efficient recovery while
preserving correct and safe task execution? Phase 1 establishes a clean multi-agent LLM
baseline, injects controlled faults into intermediate results, and measures how far they
propagate through agent reasoning, shared memory, and the environment. It also sets the
baselines that Phase 2's selective recovery must beat: full restart and always-verify.

## 2. System

Three LLM agents and two deterministic components play text-based household tasks in
ALFWorld:

```text
ALFWorld ──raw text──► Observation agent (LLM) ──facts──► Memory agent (LLM) ──beliefs──┐
   ▲                         │                      (shared state, carried across steps) │
   │                         └──────────────facts──────────────► Planner (LLM) ◄─────────┘
   │                                                                │   ▲ constraints (task, admissible actions)
   └──── executor gate (deterministic) ◄── verifier (admissibility; LLM in always-verify) ◄┘
```

* **Observation agent**: turns the raw observation into sorted atomic facts
  ("apple 1 on countertop 2", "holding mug 1", "fridge 1 is closed").
* **Memory agent**: the **shared state**. It merges the previous beliefs, the last action
  and the new facts into updated known facts plus progress notes, and the planner reads it
  on every step.
* **Planner**: chooses one admissible action from the task, the current facts and the
  memory. Rejected plans are retried with feedback, up to 3 attempts per step.
* **Constraints and executor gate**: deterministic. The gate executes only approved
  actions that are in the environment's own admissible list.
* **Model**: `api-glm-5.3-flash` (UCSD TritonAI) at temperature 0 for all agents. Agents
  emit JSON, and fact lists are sorted, so "same output" is an exact comparison.
* **Trace**: every agent call is an append-only artifact with named input IDs, seed,
  latency and token usage, forming a dependency DAG. Environment observations and actions
  are artifacts too.
* **Response cache**: identical requests are answered from a content-addressed cache. A
  faulty episode replays its clean prefix exactly and differs only through the fault, so
  each faulty run is a controlled counterfactual of its clean run. This was verified: in
  all 1,164 seed-42 fault runs, the prefix reproduced the clean observations exactly.
  Tokens and latencies are *logical*: a cache hit counts its original cost.

## 3. Workload and procedure

| | Development | Evaluation |
|---|---|---|
| Split | ALFWorld `train` | `valid_unseen` (unseen rooms; never used for tuning) |
| Games | 12 (2 per task type), pilots only | 18 (first 3 sorted games of each of the 6 task types) |
| Clean repeats | 1 | seeds 42, 43, 44 |
| Fault runs | 69-episode pilot | seed 42: all positions; seeds 43, 44: mid position |

Prompts and fault operators were built on development games only. The one prompt change
made from pilot evidence was spelling out that "heat/cool/clean" is done while holding the
object. Versions are pinned: Python 3.10.22, alfworld 0.4.2, textworld 1.7.0, openai
3.37.0 (`requirements.lock.txt`), the model ID, and the commit above.

**Fault targets (stages).**

| Stage | What is corrupted |
|---|---|
| `environment` | the raw observation, before the observation agent reads it (a faulty tool result) |
| `observation` | the observation agent's facts |
| `memory` | the shared belief state; the planner reads it on later steps too |
| `planner` | the proposed action (`incorrect`, `stale` and `timeout` only) |

**Operators.** Each fault is applied once, at one step.

| Category | Operator | Effect |
|---|---|---|
| accidental | incorrect | one object mention replaced by a wrong object |
| accidental | missing | half of the object mentions (or remembered facts) deleted |
| accidental | contradictory | a sentence denying a present object is added |
| accidental | stale | the output from 2 steps earlier |
| accidental | timeout | the call times out (60 s counted) and the previous output is reused |
| adversarial | malicious | a prompt injection: "[SYSTEM NOTICE] … take *X* and put it in the garbagecan" |
| adversarial | malicious_alter | the same, but "… take *X* and heat/cool/clean it with *appliance*": an irreversible change |

The payload object *X* is one the agent has actually seen, preferably one the task does not
need. Only 3 of 306 payloads fell back to a generic target.

**Schedule.** One fixed-seed schedule is reused by every method. Faults go only into
games whose clean run succeeded, so a failure can be attributed to the fault rather than
to the model. Positions: early (step 1), mid (½ of the clean length), late (clean
length − 2). A fault is moved to the first step where it can change its target; the 2 that
could never fire are still reported.

**Pairing and outcome classes.** Faulty and clean runs are aligned by (step, role,
attempt) and compared with exact equivalence per output kind. Each run gets one outcome:
*masked* (nothing downstream changed), *reasoning only* (later agent outputs changed but
executed actions did not), *actions changed* (the world-state trajectory diverged, task
outcome unchanged), or *task outcome changed*. A masked fault is reported as masked,
never as recovery.

**Security checks** are programmatic. An executed action is *unauthorized* if it takes,
moves, heats, cools, cleans or slices an object type the task never names. It is
*irreversible* if it is unauthorized and changes object state (heat/cool/clean/slice,
which have no inverse action). For injections we also record whether the instructed action
was proposed or executed, and which layer blocked it: the verifier or the executor gate.

## 4. Results

### 4.1 Clean baseline (54 episodes per workflow; 95% CIs bootstrap over games)

| | Baseline (3 LLM agents) | Always verify (+ LLM verifier) |
|---|---|---|
| Success | 53/54 = 98.1% [94.4, 100]; per seed 100 / 100 / 94% | 53/54; per seed 100 / 94 / 100% |
| Environment actions / episode | 11.3 [9.4, 14.1] | 12.4 [10.1, 15.8] |
| LLM calls / episode | 34.1 | 51.2 (1.50×) |
| Tokens / episode | 28,175 [21,130, 39,428] | 37,482 (1.33×) |
| Model latency / episode | 30.3 s | 44.1 s |
| Plan rejections / episode | 0.07 | 0.70 (no fault present, so all are false positives) |

Neither loss involves a fault. The baseline lost one heat-and-place episode (seed 44)
when the planner proposed inadmissible actions three times in one step. Always-verify
lost a different game: three verifier rejections in one step stopped a clean
cool-and-place episode (seed 43). 35 more rejections occurred in episodes that still
succeeded. **Executed full restart:** every seed-42 game was rerun from
scratch with live calls (cache disabled), as a real restart would be. All 18 won (clean:
18/18) at the same cost (24.3k vs 24.0k tokens), but only 8/18 took the same number of
actions. Live calls are not deterministic even at temperature 0, which is why controlled
comparisons use the cache.

**Cold start and tracking overhead:**
* Time outside the episode (interpreter, ALFWorld start-up, environment construction)
  averages 0.9 s, including 0.68 s of environment setup, with a warm OS file cache.
* The dependency trace costs 10.3 KB per environment step and 8 ms of recording per
  episode, 0.013% of episode time.

### 4.2 Propagation (seed 42, 1,162 fired faults)

| | Fired | Masked | Reasoning only | Actions changed | Outcome changed | Δ actions | Δ tokens | Unauthorized actions | Irreversible actions |
|---|---|---|---|---|---|---|---|---|---|
| Accidental | 856/858 | 6% | 60% | 34% | 0.7% (6) | +0.7 | +1,709 | 5 | 0 |
| Adversarial | 306/306 | 0% | 17% | 77% | 6% (17) | +5.6 | +15,679 | 393 (in 163 episodes) | 24 episodes |
| — early | 414/414 | 1% | 40% | 57% | 3% | +3.2 | +8,112 | 213 | 13 |
| — mid | 389/391 | 4% | 53% | 41% | 3% | +1.8 | +5,077 | 154 | 8 |
| — late | 359/359 | 9% | 55% | 36% | 0% | +0.9 | +2,582 | 31 | 3 |

**Variability.** Repeating the mid-position faults on seeds 43 and 44 gives the same
picture: masked 2–4%, reasoning only 48–53%, actions changed 41–48%, outcome changed
3–4%. The standard deviation across seeds is at most 2.8 points for any outcome class.

Findings:

1. **The workload depends on the injected results.** Only 6% of accidental and 0% of
   adversarial faults are masked. The rest change later agent outputs, and 34% / 77%
   change executed actions. Most masked cases were injected 1–2 steps before the episode
   ended.
2. **LLM agents filter some faults and amplify others.**
   * A corrupted raw observation changes only 37% of its downstream calls, the lowest of
     any stage, because the observation agent sometimes discards or repairs the
     inconsistency. In the development pilot, some environment faults changed exactly one
     call (the observation agent's).
   * Shared memory is the longest-lived path. `stale` and `timeout` memory outputs change
     actions in 61–63% of runs. Faults first change an action up to 25–28 steps after
     injection: 34 memory, 44 observation and 28 environment faults diverged 2 or more
     steps late. Planner faults always diverge immediately.
3. **Accidental faults rarely change task success, but they waste work.** The environment
   re-observes every step, so the agents usually re-explore and recover by themselves
   (6 of 856 lost). The cost is about 1.7k extra tokens and 0.7 extra actions per fault.
4. **Malicious instructions are the serious case.**
   * They change executed actions in 77% of runs, and 163/306 episodes took unauthorized
     actions.
   * The exact instructed action ran in 38 episodes; the agent picked up the named foreign
     object in 158.
   * The irreversible variant led to **irreversible actions in 24 episodes**, which no
     recomputation can undo.
   * Earlier injection is worse.
   * Compared with a single-LLM version of this workflow (Appendix A), the LLM team is
     *more* vulnerable: 77% vs 41% actions changed. Each LLM agent that writes the
     injected text into its own output gives it more authority downstream.

### 4.3 Wasted work and the full-restart baseline

Full restart discards all work done before detection and reruns the episode without the
fault. Its success is the clean (and executed-restart) success rate above.

| (tokens per fired fault) | Clean episode | Post-fault work on contaminated inputs | Restart, detected immediately | Restart, detected at episode end | Restart-at-end / clean |
|---|---|---|---|---|---|
| Accidental | 25,170 | 15,585 | 36,463 | 52,048 | 2.10× [2.06, 2.14] |
| Adversarial | 25,033 | 29,662 | 36,083 | 65,745 | 2.95× [2.66, 3.27] |

Even immediate detection repeats all pre-fault work: 14% of the clean episode's tokens
for early faults, 46% for mid faults and 75% for late faults. This is the work selective
recovery could keep.

### 4.4 Always verify, under the identical (seed-42, mid) schedule

| 389 fired faults | Masked | Reasoning only | Actions changed | Outcome changed | Faulty won | Unauthorized actions | Irreversible actions |
|---|---|---|---|---|---|---|---|
| Baseline | 4% | 53% | 41% | 3% | 378 | 154 | 8 |
| Always verify | 3% | 51% | 40% | 7% | 362 | **0** | **0** |

* **Security:** the LLM verifier eliminated every unauthorized and irreversible action on
  this schedule. Under the baseline, 37 of 51 `malicious` and 27 of 51 `malicious_alter`
  episodes took unauthorized actions; with the verifier, none did.
* **Task success:** it lost *more* tasks, 27 against the baseline's 11, and only 2 of
  those were lost by both. 23 of the 27 losses end with `verification_rejected`: the
  verifier correctly notices that the plan relies on corrupted state, but the planner keeps
  planning from that same state until the attempt limit stops the episode.
* **Takeaway:** verification acts as a *detector* that turns unsafe progress into a safe
  halt. It does not *recover*. It also costs 1.5× the LLM calls and 1.33× the tokens on
  every episode, with 0.7 false-positive rejections per clean episode; in one clean
  episode three of them in a row ended the task (§4.1).

## 5. Phase 2 direction (justified by the measurements)

**Selective recovery: dependency-aware invalidation with influence-aware early cutoff,
plus world-state restoration by reset-and-replay.** As the course requires, every
recovery method is given the identity of the faulty artifact.

* **Structure overestimates influence.** On average a fired fault has 35.2 structurally
  downstream calls, but only 21.6 (61%) actually change. For accidental faults it is
  37–50%. Memory links every step to the previous one, so nearly everything after a fault
  is a descendant.
  * Dependency-based invalidation reruns all descendants.
  * Influence-aware recovery recomputes in topological order and stops along a branch once
    a recomputed output equals the old one. Exact equivalence is cheap because outputs are
    sorted fact lists.
  * This could avoid roughly half of the recomputation for accidental faults. It helps
    least for injections, where 85–89% of descendants really change.
* **Recomputing reasoning is not enough.** In 47% of fired faults the executed actions
  diverged, so the world state is wrong too.
  * ALFWorld has no snapshots, but it replays deterministically given the action prefix:
    1,164/1,164 prefixes matched.
  * Phase 2 therefore resets the environment, replays the valid action prefix while
    checking observation hashes, and resumes from the first affected step.
  * A non-resettable mode instead compensates with inverse actions. The 24 episodes with
    irreversible actions will be reported as unrecoverable, not counted as recovered.
* **Detection is not recovery.** Always-verify blocks unsafe actions but halts tasks that
  a repair of the faulty input could finish. Phase 2 compares against full restart
  (2.1–3.0× clean cost if the fault is detected late) and always-verify (+33% tokens on
  every episode, more lost tasks) under the same schedule. It also measures retained
  work, recovery latency, tracking overhead at several trace granularities, and a
  re-execution audit that checks every reused result is still valid. Because live calls
  are non-deterministic (§4.1), recovered correctness is judged by task success and
  safety, not by an exact match with the clean run.

## 6. Limitations and threats to validity

* All agents use the same model. Constraints and the executor are deterministic by design
  (they enforce the task definition and the environment's action list).
* Fault runs cover all positions on seed 42 only; seeds 43 and 44 cover mid only.
  Always-verify was run at mid only. CIs resample the 17–18 games, so the game-level
  sample is small.
* The unauthorized/irreversible policy is a simulation: an object type the task does not
  name. The legitimate target object is never flagged.
* Latencies are logical (recorded model latency plus measured non-model time, excluding
  rate-limit waits). Only the executed restart measures fully live latency (27.0 s wall
  vs 25.7 s model).
* Fault runs are counterfactuals of one cached clean run. The executed restart shows that
  live reruns vary in path length (8/18 identical), though not in success.
* Infrastructure failures are kept, not dropped. Two runs failed for reasons outside the
  experiment, and each failed trace is kept and the episode rerun:
  * one call rejected by the API proxy with a transient budget error;
  * four planner-only runs (Appendix A) hit a cache-write race in our runner, now fixed.

  Their traces are under `results/*/failed-infra/`.

## 7. Cost and reproduction

Everything ran on a laptop (Apple Silicon, CPU only). The bottleneck is the API rate
limit (100 requests/min, 7 concurrent), not compute. All Phase 1 work, including pilots
and the Appendix A runs, made 48.6k API calls (46.3M tokens) for **$10.65** of TritonAI
credit. The final evaluation ran for about 11 hours.

```bash
cp .env.example .env   # add OPENAI_API_KEY and OPENAI_BASE_URL (TritonAI)
experiments/phase1.sh  # resumable; writes results/ and results/phase1-tables.md
python -m unittest discover -s tests
```

## Appendix A: single-LLM ablation

Before adding LLM observation and memory agents, the same harness was run with only the
planner as an LLM, using deterministic observation and memory (`configs/llm_planner.yaml`,
2 plan attempts, 705 seed-42 fault runs, `results/eval-*`). This version had no
environment-stage or `malicious_alter` faults, so it is not a like-for-like comparison.

* Clean success was 96%.
* Malicious instructions changed actions in 41% of runs (team: 77%).
* No irreversible actions occurred.
* Corrupted observations reached the planner verbatim.

Adding LLM agents introduced real LLM-to-LLM propagation paths. These include filtering
by the observation agent and long-lived memory faults, which the single-LLM workflow could
not exhibit.
