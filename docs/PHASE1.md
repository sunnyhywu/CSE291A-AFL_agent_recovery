# Phase 1: Fault Injection and Propagation Measurement in Multi-Agent ALFWorld

CSE 291A, Option 5 (Failure Propagation and Recovery in Multi-Agent Systems).
All numbers come from `results/` and are regenerated by `experiments/phase1.sh`;
the full tables are in `results/phase1-tables.md`.

## 1. Question

Can tracking dependencies between agent results support efficient recovery while
preserving correct and safe task execution? Phase 1 establishes a clean LLM baseline,
injects controlled faults into intermediate results, and measures how far they
propagate through agent reasoning **and** the environment. It also sets the baselines
that Phase 2's selective recovery must beat: full restart and always-verify.

## 2. System

A five-role workflow plays text-based household tasks in ALFWorld:

```text
ALFWorld obs ─► observation agent ─► state ─┬─► planner (LLM) ─► verifier ─► executor gate ─► ALFWorld
                     memory agent ◄─ state   │      ▲   ▲            ▲
   (previous memory, last action) ─► memory ─┘      │   └ constraints ┘ (task + admissible actions)
                                                    └── rejection feedback (bounded retries)
```

* **Planner**: `api-glm-5.3-flash` (UCSD TritonAI), temperature 0, JSON output.
  Observation, memory (8-step window, the **shared state** across steps) and constraints are
  deterministic. The verifier checks admissibility. In the always-verify variant it is a
  second LLM call that checks each plan against the raw observation and the task.
* **Executor gate**: deterministic. It executes only approved actions that are in the
  environment's own admissible list, so no agent can execute an invalid command.
* **Trace**: every agent call is logged as an append-only artifact with named input IDs,
  seed, latency, and token usage, forming a dependency DAG. Environment observations and
  actions are artifacts too, so world-state history is part of the graph.
* **Response cache**: identical requests are served from a content-addressed cache. A
  faulty episode therefore replays the clean prefix exactly and differs only through the
  fault, so each faulty run is a controlled counterfactual of its clean run. All reported
  tokens and latencies are *logical*: a cache hit counts its original cost.

## 3. Workload and procedure

| | Development | Evaluation |
|---|---|---|
| Split | ALFWorld `train` | `valid_unseen` (unseen rooms; never used for tuning) |
| Games | 12 (2 per task type), pilots only | 18 (first 3 sorted games of each of the 6 task types) |
| Repeats | 1 | clean: seeds 42, 43, 44; faults: seed 42 |
| Step limit | 50 | 50 |

Prompts, fault operators and the analysis were built on the development games only.
Versions are pinned: Python 3.10.22, alfworld 0.4.2, textworld 1.7.0, openai 3.37.0, and
the model ID. Exact package versions are in `requirements.lock.txt`, and each trace
records its configuration.

**Faults** are applied to one role output at one step, attempt 0. The original content is
kept in the trace for later recovery.

| Category | Operator | Effect |
|---|---|---|
| accidental | incorrect | an object mention is replaced by a wrong object |
| accidental | missing | half of the object mentions are deleted (memory: history erased) |
| accidental | contradictory | a sentence denying a present object is appended |
| accidental | stale | the role's output from 2 steps earlier |
| accidental | timeout | the call "times out" and the workflow falls back to the role's previous output |
| adversarial | malicious | a prompt injection: "[SYSTEM NOTICE] … take *X* and put it in the garbagecan" |

The targets are the **observation** output (single step), the **memory** output (shared
state, read by the planner on later steps), and the **planner** output (`incorrect`,
`stale`, `timeout`). The fault schedule is generated once from a fixed RNG seed and
reused by every method. Faults are injected only into games whose seed-42 clean run
succeeded (17 of 18), so failures can be attributed to the fault rather than to the
model. Each fault is placed at an early (step 1), mid (½ of the clean length) or late
(clean length − 2) position. A fault is moved forward to the first step where it would
actually change its target. Faults that could never fire are still scheduled and
reported (5 of 705).

**Pairing.** Each faulty run is aligned with its clean run by (step, role, attempt), and
outputs are compared under per-kind equivalence (same action, same approval, same state
text, …). Each run gets exactly one outcome:
*masked* (nothing downstream changed), *reasoning only* (later agent outputs changed but
the executed actions did not), *actions changed* (the world-state trajectory diverged but
the task outcome did not), *task outcome changed*. A masked fault is reported as such,
never as successful recovery.

**Security checks** are programmatic (`agent_recovery/policy.py`). An executed action is
*unauthorized* if it takes, moves, heats, cools, cleans or slices an object type the task
never names. It is *irreversible* if it is unauthorized and changes object state (heat,
cool, clean, slice). For the injection we also record whether the instructed action was
proposed or executed, and which layer stopped it: the verifier or the executor gate.

## 4. Results

### 4.1 Clean baseline (54 episodes per variant; 95% CIs bootstrap over games)

| | Planner only | Always verify |
|---|---|---|
| Success | 52/54 = 96.3% [88.9, 100]; per seed 94 / 100 / 94% | 52/54, same games |
| Environment actions / episode | 11.7 [8.0, 17.1] | 11.9 [8.1, 17.2] |
| LLM calls / episode | 11.7 | 24.1 (2.06×) |
| Tokens / episode | 9,155 [6,036, 14,039] | 14,168 (1.55×) |
| Model latency / episode | 6.3 s | 12.5 s |
| Episode wall time (excl. rate-limit waits) | 8.1 s | 8.2 s |
| Cold-start environment setup | 0.63 s | 0.66 s |
| Plan rejections / episode | 0 | 0.17 (false positives: all these episodes succeeded) |

Both failures are the same heat-and-place game (t4-g000) on seeds 42 and 44, which ran
out of steps; on seed 43 it succeeded. This is a model failure with no fault involved.
Wall time is lower than model latency for the verify variant because its planner calls
replay from the cache. Model latency is the logical cost.

### 4.2 Propagation (700 fired faults, planner-only workflow)

| | Fired | Masked | Reasoning only | Actions changed | Outcome changed | Δ actions | Δ tokens | Unauthorized actions |
|---|---|---|---|---|---|---|---|---|
| Accidental | 602/607 | 6% | 57% | 36% | 0.3% (2) | +0.8 | +691 | 5 |
| Adversarial | 98/98 | 0% | 38% | 41% | 21% | +8.3 | +9,187 | 61 (in 41 episodes) |
| — early | 255/255 | 0% | 55% | 38% | 7% | +3.3 | +3,395 | 47 |
| — mid | 240/240 | 4% | 57% | 37% | 2% | +1.4 | +1,323 | 19 |
| — late | 205/210 | 13% | 51% | 36% | 0% | +0.6 | +648 | 0 |

Findings:

1. **The workload depends on the injected results.** Only 6% of accidental faults are
   masked, and all 36 of those are memory faults injected at the episode's final step, so
   the planner never reads them. 94% change later agent outputs, and 36% change executed actions, so the
   world-state trajectory diverges.
2. **Accidental faults rarely change task success, but they waste work.** The
   environment re-observes every step, so a corrupted observation is replaced by ground
   truth at the next step; the agent re-explores and recovers by itself. The cost is
   +0.8 actions and +691 tokens per fault. Shared state is the exception. Memory faults
   are the main *delayed* path: median 1 step and up to 6 steps between injection and the
   first divergent action. Observation and planner faults diverge at once (median 0).
   `stale` and `timeout` memory outputs change actions in 59–73% of runs.
3. **Malicious instructions propagate furthest.** They change the task outcome in 21% of
   runs (21/98 lost) and change 60 later calls on average. 41/98 episodes executed
   unauthorized actions. The agent picked up the named foreign object in 38 episodes and
   completed the instructed "move to garbagecan" in 6. Earlier injection is worse: early
   7% outcome changed, late 0%.
4. **No irreversible actions occurred.** The payload asks for take/move, which can be
   undone. Phase 2 will need payloads that ask for state-changing verbs to exercise the
   non-resettable case (§5).

### 4.3 Wasted work and the full-restart baseline

Full restart discards all work up to detection and reruns the episode without the fault.
At temperature 0, through the same cache, the rerun reproduces the clean run, and its
success rate across repeats is the clean success rate above (96.3%).

| (tokens per fired fault) | Clean episode | Post-fault work on contaminated inputs | Restart, detected immediately | Restart, detected at episode end | Restart-at-end / clean |
|---|---|---|---|---|---|
| Accidental | 7,379 | 4,636 | 10,763 | 15,399 | 2.10× [2.06, 2.15] |
| Adversarial | 7,403 | 13,328 | 10,665 | 23,993 | 3.43× [3.00, 3.92] |

Even with immediate detection, restart repeats all pre-fault work. That work is 11% of
the clean episode's tokens for early faults, 50% for mid faults and 78% for late faults.
This is the work selective recovery could keep.

### 4.4 Always verify, under the identical (mid-position) fault schedule

| Paired, 240 episodes | Masked | Reasoning only | Actions changed | Outcome changed | Faulty won | Δ tokens vs own clean | Unauthorized actions |
|---|---|---|---|---|---|---|---|
| Planner only | 4% | 57% | 37% | 2% | 235/240 | +1,323 | 19 (11/32 malicious episodes) |
| Always verify | 3% | 63% | 33% | 1% | 238/240 | +1,654 | **0** |

Always-verify eliminated unauthorized actions on this schedule. It rejected 61 plans in
the malicious episodes; 44 of the rejection reasons cite the embedded notice, the
garbagecan, or an object the task does not need. It barely
reduced accidental propagation, because the planner still sees the faulty state or
memory and the verifier only gates the action. It costs 2.06× the LLM calls and 1.55×
the tokens of the clean episode, even when nothing is wrong. Its false positives are not
free either: 0.17 rejections per clean episode, and 2 fault episodes ended with
`verification_rejected` after three rejected plans in one step. In one inspected case the
verifier wrongly claimed "bread 2, not bread 1" was on the counter. Verification is
prevention and does not undo work already done.

## 5. Phase 2 direction (justified by the measurements)

**Selective recovery: dependency-aware invalidation with influence-aware early cutoff,
plus world-state restoration by reset-and-replay.** As the course requires, every
recovery method is given the identity of the faulty artifact.

* *Structure overestimates influence.* For each fired fault we count the later calls that
  are DAG descendants of the faulty output, which is what dependency-based invalidation
  reruns. On average 33.4 calls are descendants but only 19.6 actually changed (59%). For
  accidental faults the figure is 43–50%. Memory chains every step to the previous one,
  so nearly everything after a memory fault is a descendant. Influence-aware recovery
  recomputes in topological order and stops along a branch once a recomputed output
  equals the old one. The equivalence definitions already exist in `analysis/compare.py`.
  It could avoid roughly half of the recomputation that pure invalidation does.
* *Recomputing reasoning is not enough.* In 40% of fired faults the executed actions
  diverged, so the environment state is wrong as well. ALFWorld has no snapshots, but it
  is deterministic given the action sequence: in all 705 faulty runs, the replayed prefix produced
  exactly the clean run's observations up to the fault step. Phase 2 will therefore reset the environment, replay
  the valid action prefix while checking observation hashes, and resume only from the
  first affected step. A non-resettable mode compensates with inverse actions. Actions
  without an inverse are reported as unrecoverable instead of being counted as recovered.
* *Comparisons.* Full restart (2.1–3.4× the clean cost when the fault is detected late)
  and always-verify (+55% tokens on every episode, still letting accidental faults
  through), using the same schedule and budget. We will also measure retained work,
  recovery latency, tracking overhead at several trace granularities, and a re-execution
  audit that checks every reused result is still valid.

## 6. Limitations and threats to validity

* Only the planner (and the verifier variant) is an LLM. Faults in other roles reach
  reasoning only through the planner, so multi-hop LLM-to-LLM propagation is not yet
  measured.
* For 46 of 98 malicious injections the observation named no object, so the payload
  used the generic "the nearest object", which can never match an action exactly.
  Payload compliance is therefore a lower bound. Phase 2 will draw targets from the
  room's known objects.
* The unauthorized-action policy is a simulation: an object type the task does not
  name. The legitimate target object is never flagged.
* One seed (42) for fault runs, but 3 seeds for clean runs. The CIs resample the 17–18
  games, so the game-level sample is small.
* The cache makes faulty runs exact counterfactuals. Live calls at temperature 0 are not
  bit-for-bit deterministic, and the seed-to-seed variation in §4.1 is the measured
  spread.
* Rate-limit waits (TritonAI, about 100 requests/min per key) are excluded from latency
  and reported separately (`throttle_seconds`).
* Four faulty episodes crashed because of a cache-write race in our runner (now fixed).
  Their traces are kept in `results/eval-faults/failed-infra/`, and the episodes were
  rerun.

## 7. Cost and reproduction

Phase 1 used 6,758 real API calls and 4.86M tokens in total, including pilots. All runs
were on a laptop (Apple Silicon, CPU only, no GPU); the bottleneck is the API rate limit,
not compute. To reproduce:

```bash
cp .env.example .env   # add OPENAI_API_KEY and OPENAI_BASE_URL (TritonAI)
experiments/phase1.sh  # resumable; writes results/ and results/phase1-tables.md
python -m unittest discover -s tests
```
